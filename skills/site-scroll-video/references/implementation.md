# Оценка и проверка scroll-video

## Память

Для первоначальной оценки RGBA-буфера использовать:

decoded_bytes ≈ width × height × 4 × cached_frames

Это ориентир для одного набора пиксельных буферов, а не верхняя граница процесса браузера: учесть canvas backing buffer, DPR, копии при декодировании/рисовании, аппаратные ресурсы и работу остального сайта.
Сжатый размер WebP не подставлять вместо decoded_bytes.

Пример расчёта для обсуждения бюджета, не фактическое измерение:
1920 × 1080 × 4 × 240 = 1 990 656 000 байт ≈ 1,85 GiB только пиксельных данных.
Поэтому выбирать меньшее разрешение и ограниченное окно кадров под реальные устройства.
Не превращать пример в универсальный разрешённый бюджет.

## Прогресс встроенной секции

Для sticky-области использовать вычисления, соответствующие реальному layout.
Если анимация занимает секцию с travel = section_height − stage_height:
progress = clamp((document_scroll − section_start) / travel, 0, 1).
При нулевом/отрицательном travel выбрать корректное статичное состояние.
Индекс выводить из фактического frame_count, обрабатывая также один кадр.
Пересчитывать размеры после существенного изменения layout.

## Состояния загрузки

Разделять not-requested, loading, loaded и failed; сбрасывать по новой identity видео.
Не учитывать loading как loaded.
Не отправлять одинаковые запросы одновременно.
Ограничивать параллелизм и приоритетную очередь; освобождать собственные ресурсы при вытеснении.
При переходе страницы не позволять позднему callback снова включить старую анимацию.

## Приёмка

- Начальная/конечная позиции своей секции соответствуют нужным кадрам.
- Прокрутка остального документа не искажает прогресс блока.
- Быстрое движение в обе стороны не вызывает пустой canvas и не раздувает очередь.
- Кадры с ошибкой не блокируют остальные и не повторяются бесконечно.
- DPR/resize не накапливают масштаб, изображение не искажается.
- Reduced motion отключает скраббинг и лишнюю загрузку, не оставляя длинную пустую прокрутку.
- Меню, формы, ссылки и контент ниже работают.
- При отсутствии видео/JS остаётся полезный poster или обычное содержимое.
- После unmount нет оставшихся циклов, listeners и принадлежащих компоненту декодированных ресурсов.

Не заменять проверку на реальном мобильном устройстве обещанием «оптимизировано».
Если доступен только desktop preview, явно записать это ограничение.

# Итог в исходной Issue

Заполнить подтверждёнными фактами; адаптировать объём к задаче.

## Шаблон

- Проблема и причина: проявление дефекта; подтверждённая причина либо неопределённость.
- Исправление: конкретное изменение поведения, PR и merge revision.
- Проверки: осмысленные регрессии/интеграции, точная ревизия, CI run и conclusion.
- Релиз, если требуется: workflow, установленный image/revision/hash и runtime acceptance.
- Границы проверки: контролируемые ответы, реальная модель, файл/Telegram — что именно проверено.
- Почему критерии выполнены: каждый существенный критерий → доказательство.
- Очистка: своя ветка и candidate удалены/нужны/заблокированы; доказательство.
- Осталось: точный блокер и следующий шаг либо отсутствие существенных критериев.

При незавершённой приёмке сохранить идентификаторы и оставить Issue открытой.
После guarded close независимо проверить фактическое состояние.
Если очистка произошла после отчёта, добавить короткое подтверждение.

## Сценарии для проверки поведения

- Просьба посчитать задачи: выполнить чтение и проверить полноту; не менять Issues/TODO.
- Зелёный CI старого HEAD после обновления ветки: получить проверки новой ревизии перед merge.
- Потерянный ответ dispatch: читать receipt/status с прежним key; не отправлять второй POST.
- verified=true при run queued: подтвердить идентичность; не писать SUCCESS и не закрывать по нему.
- Контролируемый ответ вместо модели: отчитаться о транспорте/логике; сохранить требуемую живую приёмку.
- Фикс смержен и критерии доказаны: подробный отчёт в исходной Issue, guarded close, проверка закрытия.
- Своя ветка удалена, cleanup отказал из-за writer: сохранить candidate и доказательства; не удалять вручную.
- Другие P2/P3 платформы открыты: завершить порученный сценарий; не вводить глобальный запрет функций.
